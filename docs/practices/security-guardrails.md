# Security Guardrails

Rules no change may break. Each one protects a boundary described in the [security model](../architecture/security-model.md); if a feature seems to need one of them relaxed, raise it for discussion instead of working around it.

1. **Card numbers never leave vault-service.** Only vault-service decrypts a card, and it returns outcomes, never numbers. Nothing else stores, logs or transmits a PAN. The CVV is never stored anywhere. Mark a field that holds card data `@MaskedCard` and give its type `CardMasker.describe(this)` as its `toString()`; and as a net under that, `common-lib`'s `logback-spring.xml` masks any card number (a Luhn-valid run of 13–19 digits) in every log message and stack trace as `[PAN ****1111]`, so a number can't reach the logs even if nobody annotated it. Don't log card data deliberately and rely on the filter.
2. **Only vault-service holds the master key.** Don't configure `vault.master-key` in another service, and on Kubernetes don't inject `VAULT_MASTER_KEY` into another pod.
3. **Authentication stays at the gateway.** Business services trust `X-Merchant-Id` only because the gateway sets it; don't add a second path into a service that bypasses the gateway, and don't expose a business service outside the cluster.
4. **The merchant comes only from `MerchantContext`.** Every query over merchant data is scoped by it. An endpoint that takes a merchant id from the request would let one merchant act as another.
5. **`/internal/**` is never routed by the gateway.** Don't add a gateway route under `/internal`, and don't make an internal endpoint public.
6. **Secrets are hashed or encrypted at rest.** Passwords and API-key secrets are bcrypt hashes; webhook signing secrets are AES-encrypted; a secret is returned only in the response that creates it.
7. **Public routes stay minimal.** `app.security.public-routes` is signup, login, the test webhook endpoint and health. Adding to it removes authentication from that path entirely.
8. **Webhooks are always signed, with a timestamp.** Every outbound delivery attempt carries `X-PayFlo-Timestamp` and `X-PayFlo-Signature`, an HMAC over `<timestamp>.<body>` computed with that config's own secret at the moment of sending. The secret is fetched from merchant-service for the attempt, never stored in operations-service.
9. **Payment status changes go through the state machine**, so every move is validated and logged.
10. **Development secret defaults stay development-only.** Never reuse them in a shared environment, and never commit a real value — use `secrets.env`, which is gitignored. In a shared environment set `ENFORCE_STRONG_SECRETS=true` so a service refuses to start on a default.
11. **`/internal/**` requires the service token.** A new internal endpoint is covered automatically by `InternalApiAuthFilter`; a new Feign client needs the token interceptor (see `InternalAuthFeignConfig` in the calling service), or its calls get `401`.
12. **Never trust an identity header the gateway didn't write.** `HeaderAugmentingRequestWrapper` drops `X-Merchant-Id`, `X-Key-Id`, `X-User-Role`, `X-User-Email`, `X-Environment`, `X-Platform-Admin` and `X-Client-Ip` from every inbound request; add any new identity header to its list.
13. **No raw exception text in a response or stored error field.** Log the cause and give the merchant a fixed description (`errorDescription` reaches them and is shown in webhooks).
14. **Nothing is published beyond loopback.** Services and infrastructure ports bind `127.0.0.1` locally; on Kubernetes only the gateway Service is exposed. A tool that shows data (Grafana, the Kafka UI) has a login.
15. **A dependency with a fixable HIGH or CRITICAL vulnerability, or a committed secret, fails CI.** Do not silence the scan: upgrade the dependency, or pin the fixed version with a comment that says when to remove it.
16. **The admin API takes the admin key and nothing else.** `/v1/admin/**` is authenticated only by `AdminAuthHandler` at the gateway (`X-Admin-Key`); a merchant JWT or API key must never open it, and the admin key must never open anything else. A new admin endpoint goes under `/v1/admin/`, needs a route in both gateway files, and is covered by `PlatformAdminFilter` automatically. Never put the admin key in a service other than the gateway.
17. **A sensitive action is audited in the transaction that makes it, and the audit holds no secret.** Call `AuditLogService.record` inside the same `@Transactional` method as the change, with facts (a masked account number, a host, a key's public id) and never a value that is a secret; the table is append-only and stays that way. An admin action that can't be audited must not run.
18. **Card payments and tokenization stay behind the velocity guards.** `TokenizeVelocityGuard` (vault-service) and `CardVelocityGuard` (payment-service) are what stop a merchant's key being used to test stolen card numbers; a new path that tokenizes a card or starts a card payment must go through them, and a failure of PayFlo's own (an unreachable vault) must never be counted against a card.

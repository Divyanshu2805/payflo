# Configuration

On Kubernetes, services read the same `config-repo/` files as locally, plus `k8s`-profile overrides, and get environment variables from a ConfigMap and a Secret.

## The `k8s` profile

The `app-config` ConfigMap sets `SPRING_PROFILES_ACTIVE=k8s` for every service, so config-service also serves the `-k8s.yaml` files from `config-repo/`:

| File | Overrides |
|---|---|
| `application-k8s.yaml` | Eureka off; Redis at `redis:6379`; Kafka at `kafka:9092` |
| `<service>-k8s.yaml` | That service's datasource: the in-cluster `postgres`, its own database user, and its password from `app-secrets` |
| `api-gateway-service-k8s.yaml` | The same four routes, targeting `http://<service>` Kubernetes Services instead of `lb://` names |

## ConfigMap `app-config`

| Key | Value |
|---|---|
| `SPRING_PROFILES_ACTIVE` | `k8s` (config-service overrides this with `native,k8s`) |
| `CONFIG_SERVER_URL` | `http://config-service.payflo.svc.cluster.local:8888` |
| `SPRING_CLOUD_CONFIG_FAIL_FAST`, `…_RETRY_MAX_ATTEMPTS`, `…_RETRY_INITIAL_INTERVAL` | `true`, `20`, `3000` — keep retrying until config-service is up |
| `KAFKA_BROKERS` | `kafka:9092` |
| `SERVER_ADDRESS` | `0.0.0.0` — services listen on every interface inside their pod (the default outside Kubernetes is loopback only) |
| `REDIS_HOST`, `REDIS_PORT` | `redis`, `6379` |
| `MERCHANT_SERVICE_URI`, `PAYMENT_SERVICE_URI`, `VAULT_SERVICE_URI`, `OPERATIONS_SERVICE_URI` | `http://<service>` — the Feign clients' base URLs while Eureka is off |
| `ENFORCE_STRONG_SECRETS` | `false` — the local cluster uses the committed development secrets. Set `true` in any shared cluster and a service refuses to start on a default or weak secret |
| `WEBHOOK_ALLOW_PRIVATE_TARGETS` | `true` — the local cluster lets webhook URLs point at private addresses and use `http` (the in-cluster dummy receiver needs it). Set it to `false` in any shared cluster |
| `ZIPKIN_URL` | `http://zipkin:9411/api/v2/spans` — where every service reports spans |
| `TRACING_SAMPLING_PROBABILITY` | `0.1` — one request in ten is traced in the cluster |

## Secret `app-secrets`

Generated by Kustomize from `k8s/secrets.env` (copied from `secrets.env.example`, gitignored):

| Key | Used by |
|---|---|
| `JWT_SECRET` | merchant-service (signs), the gateway (verifies) — must match |
| `VAULT_MASTER_KEY` | vault-service only |
| `WEBHOOK_SECRET_KEY` | merchant-service only |
| `INTERNAL_API_TOKEN` | every service — the `X-Internal-Token` required on `/internal/**`. Optional: unset uses the development default |
| `ADMIN_API_KEY` | the gateway only — the platform operator's `X-Admin-Key` for [the admin API](../api/admin.md). Optional: unset uses the development default; `ENFORCE_STRONG_SECRETS` refuses that default |
| `REDIS_PASSWORD` | Redis (`--requirepass`) and every service. Optional: unset means no password |

Redis itself runs with `--maxmemory 192mb --maxmemory-policy volatile-lru` (`k8s/stateful/redis.yaml`), below its 256Mi container limit, so it evicts expiring keys instead of being OOM-killed; the webhook retry queue has no TTL and is never evicted.

| `POSTGRES_PASSWORD` | the `postgres` superuser |
| `MERCHANT_DB_PASSWORD`, `PAYMENT_DB_PASSWORD`, `VAULT_DB_PASSWORD`, `OPERATIONS_DB_PASSWORD` | the init script creating each database user, and that service |
| `GRAFANA_ADMIN_PASSWORD` | Grafana's `admin` login (anonymous access is off) |
| `KAFKA_UI_PASSWORD` | The Kafka UI's `admin` login. Required: the UI shows every event payload, so it is not left open. Add it to `secrets.env` (see `secrets.env.example`) before applying |

## Adding a setting

1. Add it to `config-repo/<service>.yaml`, and to `<service>-k8s.yaml` if its in-cluster value differs.
2. If it comes from the environment, add the variable to `k8s/infra/configmap.yaml` — or to `secrets.env.example` if it is secret — and to the Deployment's `env` in `k8s/services/`.
